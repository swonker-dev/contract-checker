# MVP проверки трудовых договоров

Прототип предлагает выбрать тип договора, принимает текстовый DOCX или PDF,
разбивает документ на пункты, проверяет однозначные числовые ограничения правилами,
находит релевантные фрагменты локальной нормативной базы и передаёт пункты выбранной LLM.

## Текущий статус

Реализован первый технический каркас:

- извлечение текста из DOCX и PDF;
- каталог типов документов; сейчас активен профиль трудового договора;
- базовая анонимизация email, телефонов, паспортов, СНИЛС и ИНН;
- структурное чанкирование по нумерованным пунктам;
- локальный поисковый индекс;
- сменные реализации embeddings;
- детерминированные проверки продолжительности рабочей недели, отпуска,
  периодичности выплаты зарплаты и срока испытания;
- несколько независимых замечаний для одного пункта договора;
- семантическая проверка запускается даже при срабатывании числового правила;
- проверка всего договора на отсутствующие или неконкретные место работы,
  трудовую функцию, размер оклада и режим работы; с реальной LLM используется
  отдельная проверка смысла всего договора, regex остаются резервным режимом;
- mock-режим, клиент GigaChat API и клиент OpenAI-совместимого Chat Completions API;
- повторный запрос к LLM, если первый ответ не соответствует JSON-схеме;
- строгий структурированный вывод GigaChat через `response_format=json_schema` с
  автоматическим откатом на промпт и повторный запрос, если тариф его не поддерживает;
- отдельный статус ошибки обработки, не смешанный с юридическими предупреждениями;
- проверка цитат и консервативный вывод: чанковая LLM публикует только прямые
  нарушения с точными цитатами; свободные предупреждения и неподтверждённые
  выводы скрываются;
- Markdown-отчёт, CLI, FastAPI API и веб-интерфейс с фоновым анализом и polling.

В `data/regulations` находится первый нормативный пакет по статьям 57, 70, 91,
100, 115 и 136 ТК РФ. В `data/contracts` находятся десять корректных и десять
проблемных демонстрационных договоров. Пользовательский ключ GigaChat хранится
только в локальном `.env`.

## Установка

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
Copy-Item .env.example .env
```

Для локальной multilingual embedding-модели:

```powershell
pip install -e ".[semantic,dev]"
```

При первом использовании sentence-transformers может потребоваться загрузка модели.

## Запуск API

```powershell
python -m contract_checker serve
```

Веб-интерфейс будет доступен по адресу `http://127.0.0.1:8000/`,
документация API — `http://127.0.0.1:8000/docs`.

На главной странице доступны карточки типов документов. Трудовой договор ведёт
на `/check/employment-contract`; NDA и договор услуг пока отображаются как будущие
профили и не принимают файлы.

Фоновый API:

- `GET /api/document-types` — каталог типов;
- `POST /api/analyses` — создать анализ из `document_type_id` и файла;
- `GET /api/analyses/{analysis_id}` — получить статус и готовый результат.

Состояния и готовые результаты хранятся в локальном SQLite. Загруженный исходный
файл используется во временной директории и удаляется после обработки.

## Проверка файла через CLI

```powershell
python -m contract_checker analyze .\example.docx
```

По умолчанию используется `LLM_PROVIDER=mock`, поэтому реальный юридический анализ
не выполняется.

## Настройка GigaChat 2 Lite

В документации GigaChat модель называется GigaChat 2 Lite, но её идентификатор
в API — `GigaChat-2`.

Создайте `.env` и укажите ключ авторизации из личного кабинета GigaChat API:

```dotenv
LLM_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=base64-authorization-key
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2
GIGACHAT_BASE_URL=https://api.giga.chat/v1
GIGACHAT_AUTH_URL=https://ngw.devices.sberbank.ru:9443/api/v2/oauth
GIGACHAT_VERIFY_SSL=true
```

`GIGACHAT_CREDENTIALS` — это authorization key для получения временного access
token, а не сам access token. Приложение получает access token автоматически и
переиспользует его в течение одной сессии.

### Совместное использование в учебной группе

Для знакомства с проектом ключ GigaChat не требуется: оставьте в локальном
`.env` значение `LLM_PROVIDER=mock`. В этом режиме приложение работает без
обращений к внешней модели, но реальный семантический анализ не выполняется.

Для полноценной демонстрации каждый участник может получить собственный ключ
GigaChat API. Физическим лицам доступен бесплатный Freemium-режим для личного
некоммерческого использования: зарегистрируйтесь в личном кабинете, создайте
проект GigaChat API и получите Authorization Key по
[официальной инструкции](https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart).
Актуальная бесплатная квота и срок её действия указаны на странице
[тарифов для физических лиц](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs).

Если группа использует один общий учебный ключ, передавайте его только
участникам группы по закрытому каналу. Каждый участник должен самостоятельно
записать собственный или общий ключ в локальный `.env`:

```dotenv
LLM_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=group-authorization-key
GIGACHAT_SCOPE=GIGACHAT_API_PERS
```

Не добавляйте общий ключ в README, `.env.example`, исходный код или историю Git,
в том числе в приватном репозитории. Файл `.env` уже исключён через `.gitignore`.
Владелец общего ключа отвечает за всю израсходованную квоту: любой получивший
ключ может обращаться к API независимо от этого приложения. После защиты
проекта или при подозрении на утечку перевыпустите ключ. Перевыпуск блокирует
старый ключ, но не восстанавливает уже потраченную квоту.

Для GigaChat нужен корневой сертификат НУЦ Минцифры. Стандартное хранилище
сертификатов Python обычно его не содержит, поэтому без настройки возникает
ошибка `CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain`.

1. Скачайте `Russian Trusted Root CA` с портала Госуслуг по инструкции GigaChat:
   <https://developers.sber.ru/docs/ru/gigachat/certificates>.
2. Сохраните PEM-сертификат, например как
   `C:\Users\username\certs\russian_trusted_root_ca_pem.crt`.
3. Укажите абсолютный путь в `.env` (на Windows удобнее использовать `/`):

```dotenv
GIGACHAT_CA_BUNDLE_FILE=C:/Users/username/certs/russian_trusted_root_ca_pem.crt
```

После этого снова выполните `python -m contract_checker check-gigachat`.
Не отключайте проверку TLS: authorization key передается при получении токена.
Ключ нельзя сохранять в Git.

## Альтернативный OpenAI совместимый API

Для OpenAI-совместимого Chat Completions API:

```dotenv
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://example.com/v1
LLM_MODEL=model-name
LLM_API_KEY=secret
```

Ключ нельзя сохранять в Git. Если выбранная модель использует другой протокол,
нужно добавить отдельный клиент в `src/contract_checker/llm_client.py`.

### Проверка подключения

После заполнения `.env` выполните:

```powershell
python -m contract_checker check-gigachat
```

Команда получает временный access token, запрашивает список доступных моделей и
отмечает выбранную `GigaChat-2`. Authorization key в вывод не попадает.

## Настройка поиска

Офлайн-режим, пригодный для тестов:

```dotenv
EMBEDDING_PROVIDER=hashing
```

Семантический режим:

```dotenv
EMBEDDING_PROVIDER=sentence_transformers
EMBEDDING_MODEL=sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2
```

`hashing` является лексическим baseline и не заменяет настоящие embeddings.

## Нормативные источники

Пример формата находится в `data/regulations/source.example.json`. Активные файлы
можно загружать, архивировать и повторно активировать на странице
`http://127.0.0.1:8000/regulations`. Перезапуск приложения не требуется: индекс будет
перестроен при следующей проверке. Административная страница MVP не имеет авторизации,
поэтому сервер следует запускать только локально.

## Дизайн интерфейса

Каталог договоров, экран проверки и нормативная база оформлены по брендбуку
ViWork версии 1.0 от 30.09.2026. Общий каркас страниц находится в
`src/contract_checker/ui_layout.py`, цвета и компоненты — в
`src/contract_checker/static/ui.css`.

Inter и логотип загружаются локально из `/static/`. Подключение к внешнему CDN
для отображения интерфейса не требуется. Лицензия шрифта находится рядом с ним
в `Inter-LICENSE.txt`.

Описание применённых правил: [ViWork в проекте](docs/viwork-design.md).

## Демонстрационная оценка

Разметка ожидаемых замечаний находится в `evals/demo_cases.json`. Локальная
проверка только детерминированных правил не расходует токены GigaChat и
сохраняет отчёты в `evals/results-rules`:

```powershell
python -m contract_checker evaluate-demo --rules-only
```

Полный прогон всех двадцати договоров использует настроенную LLM и сохраняет
отчёты вместе с `summary.json` в `evals/results`:

```powershell
python -m contract_checker evaluate-demo
```

Для одного договора можно повторяемо указать `--case`, например:

```powershell
python -m contract_checker evaluate-demo `
  --case problematic/problematic_01_multiple_violations.docx
```

Первый полный baseline на десяти демонстрационных договорах: precision `0.607`,
recall `0.708` (17 совпадений с разметкой из 24 ожидаемых, 28 выданных
агентом замечаний). Это предварительная метрика на синтетическом наборе,
а не юридически валидированная оценка.

После добавления проверок всего договора rule-only baseline составляет:
precision `1.000`, recall `0.792` (19 из 24 ожидаемых замечаний). Полный baseline
с GigaChat `0.607` / `0.708` был получен до этого изменения и должен быть
пересчитан при следующем полном прогоне.

Расширенный rule-only baseline на 20 договорах и 31 ожидаемом замечании:
precision `0.541`, recall `0.645`. Снижение обусловлено более естественными синонимами,
составными условиями и разными стилями договоров 06-10; эти кейсы не подгонялись под
текущие регулярные выражения.
